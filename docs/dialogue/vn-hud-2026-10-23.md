## Use

Keep the existing `Start_Eagle_Lab_With_Sidecar.bat`. F7 -> Paimon -> Call & talk -> F9. The Phone closes and Paimon appears as before.

- A dark blue dialogue panel, soft gold Paimon nameplate, reply text, three conversation choices and a separate typing field replace repeated GTA caption messages.
- UP/DOWN cycles through the three suggestions and the free typing field. ENTER sends the highlighted suggestion or your typed message. Start typing to leave suggestion selection; numbers remain literal input. BACKSPACE edits; TAB leaves.
- Every input turn samples three distinct prompts from 36 English prompts, including small talk, travel, nearby activities, observed history, game portfolio/loans and current-day EagleTimes. The set stays stable while typing. A later set may include a prompt from an earlier turn.
- ENTER can advance a completed reply early. After six seconds input resumes automatically, keeping the reply visible while composing. Waiting/reply states disable suggestion sending.
- While the dialogue is visible, the minimized Phone/GPS pill is hidden to avoid overlapping the panel; existing top event notifications still render. Opening Phone ends the native conversation as before.

## Implementation and ownership

Native sources: `tools/eagle-dialogue/bridge/paimon.py`, `bridge/choices.py`, `build_paimon.py`. Renderer source: `hud/paimon_hud.lua`; `build_vn_hud.py` inserts the trusted choice pool and adds a narrow draw hook to the latest runtime HUD. The backend/AI API, persona, 2010 date/news gates, memory, skin and launcher remain unchanged by this revision.

The native script writes a bounded plain-text `cleo/EagleDialogue/ui.dat` snapshot at most 10 Hz while interactive, plus state transitions/startup/cleanup. Lua polls at 10 Hz using existing `DeltaMS()`. User/model text is parsed as data and never executed. Matching epoch/revision trailers reject incomplete writes; the renderer requires an advancing writer before adopting an active snapshot and expires stale state after 1.5 seconds. Accepted replies have a separate owned buffer so an invalid/torn backend response cannot leak into the UI. No new shared RAM mailbox.

`ui.dat` has exactly 14 LF-terminated lines: header `EAGLE_DIALOGUE_UI_V1`; bridge epoch; UI revision; native tick_ms; numeric state; selected row0..3; choice ID1; ID2; ID3; input<=100 ASCII; accepted reply<=160 ASCII; repeated revision; repeated epoch; `END`. Interactive states are2/3/4. Choice IDs are 1-based and defined by the generated `native/paimon-choice-pool.json`.

Primary CLEO5v5.0.3 source confirms `0AD9` uses a511-byte formatted-output buffer (510 bytes plus NUL), sufficient for this bounded snapshot (under360 bytes). Its `%s` precision is not enforced by the native formatter; safety comes from the explicit NUL-terminated input100/accepted-reply160 bounds, not the format precision. The 14-line trailer is therefore not truncated by a255-byte formatting limit.

The current runtime HUD includes Antigravity's debugger/error wrapper, while its source mirror lacked that update.
